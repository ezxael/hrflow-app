# HRFlow visual direction

## Identity

HRFlow is a practical HR operations desk for a corporate office. It should feel exact, calm, and easy to scan when an administrator has a queue of requests to process.

## Personality and mood

Crisp and structured, with a little human warmth in the writing and paper-like surfaces. Keep the operational information in front; use decoration only to clarify grouping, hierarchy, or status.

## Palette

- Ink: `#202722` for primary text and dark navigation.
- Muted text: `#66706A` for supporting details.
- Canvas: `#F3F4EF` for the application background.
- Surface: `#FFFFFF` for working areas.
- Pine: `#236B52` for primary actions and the current section.
- Pale pine: `#E8F1EA` for selected and calm success states.
- Amber: `#90500A` with `#FBF0DE` for requests that need attention.
- Brick: `#913C34` with `#F7EAE7` for errors and rejected requests.
- Rule: `#E5E8E1` for separators.
- Control edge: `#7A867E` and focus ring: `#4F7E5A` keep controls and keyboard focus visible.

## Typography

Use a local system sans-serif stack so the prototype works offline. Keep headings compact and sentence-case. Use tabular figures for time, dates, and counts.

## Layout and motion dials

- ENERGY: 2. A composed interface with deliberate contrast in the navigation and status colors.
- RHYTHM: 3. Tight, consistent tables and clear spacing between different work areas.
- MOTION: 1. Use short state transitions only when they explain a menu, dialog, or navigation change.

## Product UI principles

- Give each screen one primary action, based on the job on that screen.
- Treat schedules and approval queues as working tools, not decorative dashboard cards.
- Use status labels and color consistently across the app.
- On narrow screens, replace the desktop rail with a compact labeled navigation pattern and reflow tables into readable rows.
- Avoid remote fonts, imagery, and icon libraries so the app remains usable offline.
